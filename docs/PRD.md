# PRD — Wordrobe (멋지게 말하기 / Say Awesomely)

> 정식 명칭: **Wordrobe** (확정 2026-05-29).
> 작성일: 2026-05-29 · 버전: 0.2
> 갱신: 2026-06-01 — M1 MVP가 **GitHub Pages 베타**로 출시됨 (`https://littleanti.github.io/wordrobe/`). LLM은 단일 모델 `gemini-3.1-flash-lite`로 통일, 온보딩에 BYOK 보안/프라이버시 풀 가이드 적용.

---

## 1. 제품 개요

웹 서핑 중 마주친 "멋진 글귀"를 수집하고, 그 글귀들에서 자동 추출한 **말투·배경지식 페르소나 메모리**를 바탕으로 사용자가 대충 쓴 문장을 "그 말투처럼" 다듬어 주는 멀티플랫폼 LLM 라이팅 어시스턴트.

- **형태**: 웹앱(PWA) 단일 코드베이스 → 크롬 익스텐션 · iOS · Android로 배포
- **LLM**: Google AI Studio (Gemini API) — 사용자가 본인 API 키 입력
- **서버 부담**: 정적 자산 전달만 (앱 로직과 LLM 호출은 모두 브라우저에서 직접 수행)

---

## 2. 비전 & 미션

- **비전**: "내가 닮고 싶은 말투"를 옷장처럼 모아두고, 필요할 때 그 톤으로 갈아입는다.
- **미션**: LLM에게 매번 어떤 톤으로 써달라고 길게 설명하지 않게 한다. 페르소나는 사용자가 평소에 모아둔 글귀로 자동 학습된다.

---

## 3. 문제 정의

| 문제 | 현재 사용자의 우회 행동 |
|---|---|
| ChatGPT/Gemini에 매번 "이런 톤으로 써줘" 길게 설명해야 함 | 프롬프트를 메모장에 복붙 보관 |
| 멋있다 싶은 글귀를 봐도 흘려보냄 | 노션/메모장에 산발적으로 저장하지만 다시 안 봄 |
| 페르소나 프롬프트를 만들어도 톤이 점점 흐려짐 | 주기적으로 직접 다시 손봄 |
| 모바일에서 글을 다듬으려면 앱 전환이 번거로움 | 결국 안 함 |

**핵심 가설**: "수집된 글귀 → 페르소나 메모리"가 자동 갱신되면, 사용자는 LLM에 톤을 설명하지 않고 본문만 입력해도 만족스러운 결과를 얻을 수 있다.

---

## 4. 타겟 사용자

### Primary
- **블로거 / 뉴스레터 작성자 / 1인 크리에이터**: 일관된 톤을 유지하고 싶지만, 매번 톤을 잡는 데 시간이 든다.
- **외국어 SNS 사용자**: 영어/일본어로 "그럴듯하게" 쓰고 싶지만, 자기 톤이 흐릿하다.

### Secondary
- **이메일/슬랙 커뮤니케이션에 신경 쓰는 직장인**
- **자기소개서·발표문 작성 학생**

### 비-타겟
- 전문 카피라이팅 팀 (협업 기능 필요)
- 출판물 교정 (장문/스타일가이드 엔진 필요)

---

## 5. 핵심 가치 제안

1. **무설치 가까운 경험** — 웹앱 단일 코드. 크롬 익스텐션·모바일은 같은 PWA를 감싼다.
2. **본인 글귀로 만드는 페르소나** — 외부 LLM에 톤을 설명할 필요 없음.
3. **본인 API 키 = 본인 데이터** — 모든 LLM 호출이 브라우저→Gemini 직통. 운영자가 사용자 텍스트를 보지 않는다.
4. **언제든 톤 미리보기** — 페르소나 메모리는 사람이 읽을 수 있는 마크다운(`PERSONA.md` 스타일).

---

## 6. 사용자 시나리오 (User Stories)

### S1 — 글귀 수집 (브라우저)
> 사용자가 미디엄 글을 읽다가 마음에 드는 문단을 드래그 → 우클릭 → "Wordrobe에 저장" 클릭. 토스트로 "저장됨" 확인. 페르소나 메모리는 백그라운드에서 갱신.

### S2 — 글귀 수집 (모바일)
> 사용자가 모바일 브라우저에서 트윗을 길게 눌러 선택 → 공유 시트 → Wordrobe → "글귀로 저장" 탭. 앱이 열리지 않아도 저장 완료.

### S3 — 수동 붙여넣기
> 사용자가 Wordrobe 앱을 열고 "글귀 추가" 입력창에 직접 붙여넣음. 출처 URL은 선택 입력.

### S4 — 페르소나 미리보기
> 사용자가 "내 페르소나" 탭에서 자동 생성된 마크다운을 본다. 톤 키워드 / 자주 쓰는 표현 / 회피 표현이 섹션별로 나열돼 있다. 직접 편집도 가능.

### S5 — 멋지게 변환
> 사용자가 "오늘 회의 늦어서 미안" 같은 거친 문장을 입력 → "멋지게" 버튼. 페르소나 메모리 기반으로 변환된 결과 1~3안이 표시된다. 복사 버튼으로 클립보드에 복사.

### S6 — 모바일 공유 시트로 변환
> 사용자가 슬랙에서 작성 중인 문장을 길게 눌러 선택 → 공유 시트 → Wordrobe → "멋지게 변환" → 변환된 텍스트가 클립보드에 자동 복사된 채로 슬랙으로 돌아옴.

## 7. 기능 명세

### 7.1 MVP (Phase 1)

| ID | 기능 | 설명 |
|---|---|---|
| F-01 | API 키 등록 | 첫 진입 시 Gemini API 키 입력. localStorage 저장. 마스킹 표시. |
| F-02 | 글귀 수동 추가 | 텍스트 + 출처 URL(선택) 입력 후 저장. |
| F-03 | 글귀 목록/검색 | 저장한 글귀를 카드 리스트로 표시. 키워드 검색. |
| F-04 | 글귀 삭제/편집 | 개별 삭제, 본문 편집. |
| F-05 | 페르소나 메모리 생성 | 저장 글귀 5개 이상 시 자동 생성. 사용자 트리거 버튼도 제공. |
| F-06 | 페르소나 메모리 편집 | 사람이 읽는 마크다운 형태. 직접 수정 가능. |
| F-07 | 멋지게 변환 | 입력 텍스트 + 페르소나 → 변환 결과 1~3안. |
| F-08 | 결과 복사 | 클립보드 복사 + 토스트. |
| F-09 | 데이터 내보내기/가져오기 | JSON 백업/복원. |

### 7.2 Phase 2 — 크롬 익스텐션

| ID | 기능 | 설명 |
|---|---|---|
| F-10 | 우클릭 컨텍스트 메뉴 "글귀 저장" | 드래그한 텍스트 + 현재 URL을 저장. |
| F-11 | 익스텐션 팝업 | 미니 뷰. 빠른 글귀 추가 + 빠른 변환. |
| F-12 | 웹앱 ↔ 익스텐션 데이터 동기화 | 같은 origin의 IndexedDB 공유 (또는 chrome.storage). |

### 7.3 Phase 3 — 모바일 (PWA + 패키징)

| ID | 기능 | 설명 |
|---|---|---|
| F-13 | iOS/Android 공유 시트 수신 | 선택한 텍스트를 Wordrobe로 전송. |
| F-14 | 오프라인 캐시 | 글귀 열람·편집은 오프라인 가능. 변환은 온라인 필요. |
| F-15 | 홈 화면 추가 | PWA install 프롬프트. |

### 7.4 Phase 4 — 가능성 검토 (별도 검증 필요, [[trd-keyboard]] 참조)

| ID | 기능 | 메모 |
|---|---|---|
| F-16 | 키보드 익스텐션 | Gboard/삼성/Apple 키보드의 툴바 버튼으로 "멋지게 변환". 네이티브 IME 개발 필요 — TRD 분석 결과에 따라 결정. |

## 8. 사용자 흐름 (Happy Path)

```
[웹 서핑] ─drag→ [우클릭: 저장] ─→ [IndexedDB]
                                        │
                                        ↓
                                [페르소나 메모리 갱신]
                                        │
[대충 쓴 문장 입력] ──────────────────→ [Gemini 호출 (브라우저 직통)]
                                        │
                                        ↓
                                [멋진 변환 결과 1~3안]
                                        │
                                        ↓
                                  [복사/사용]
```

## 9. UX 원칙

1. **3-탭 구조 유지** — `글귀` · `페르소나` · `변환`. 그 이상은 메뉴에 숨김.
2. **API 키 분실 = 사용 불가**라는 점을 첫 화면에서 명시.
3. **변환 버튼은 1초 내 응답 시작** (스트리밍).
4. **모든 LLM 호출 전후로 어디로 데이터가 가는지 명시** — 온보딩에 BYOK 가이드(저장 위치·전송 대상·키 제한·예산/쿼터·데이터 손실)를 ko/en으로 제공.
5. **다국어** — UI는 한/영. 변환 자체는 입력 언어 자동 감지.

## 10. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 콜드 스타트 | 첫 로드 3초 이내 (정적 호스팅 가정) |
| 변환 응답 시작 | 1.5초 이내 (스트리밍 첫 토큰) |
| 오프라인 | 글귀 열람/편집 가능, 변환 시 안내 |
| 데이터 보존 | IndexedDB. 사용자 의도적 삭제 외 자동 만료 없음 |
| 프라이버시 | 글귀·API 키 일체 자체 서버로 송신하지 않음 |

---

## 11. 성공 지표 (가설 검증용)

- **Activation**: 가입 후 7일 내 글귀 5개 이상 저장 비율 ≥ 40%
- **Retention (D14)**: 변환 기능 2회 이상 사용 사용자 비율 ≥ 25%
- **Quality proxy**: 변환 결과 "복사" 클릭률 ≥ 60% (변환 1회당)
- **Persona depth**: 활성 사용자 평균 글귀 수 ≥ 15개

서버 분석 인프라가 없으므로 클라이언트 익명 집계 (Plausible / 자체 카운터) 도입 여부는 PLAN에서 결정.

## 12. Out of Scope (v1)

- 협업 / 공유 페르소나
- 클라우드 동기화 (다중 기기 간) — Phase 5 이후 검토
- 결제 / 구독 (사용자 자체 API 키이므로 불필요)
- 자체 LLM 호스팅
- 풍부한 텍스트 편집기 (마크다운 평문만)
- 음성 입력
